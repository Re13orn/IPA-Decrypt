# 优化建议（按优先级）

以下是优化路线。首轮已同步两端 Store 自动恢复、补充失败入口、原包结构检查和中断记录恢复；后台续传、暂停与完整任务状态机尚未完成。详见 CHANGELOG.md。本次整理以保留当前可用认证、数据及界面行为为主。

| 优先级 | 改进 | 用户收益 / 验收标准 |
| --- | --- | --- |
| P0 | 两端统一账户状态机：未登录、登录中、待验证码、有效、需重新认证 | 不再把按钮置灰而不给原因；账户切换不会让原任务使用新账户。将 Mac 自动恢复规则迁移到 iOS，并验证旧数据 |
| P0 | 下载任务恢复、取消和失败动作 | 失败记录直接“重试下载/只重试解密/重新登录/切账户/删除”；原包可复用，进程重启后显示可恢复状态；重试要有上限 |
| P0 | 首次开源可复现构建与资源许可闭环 | 新开发者按文档取得依赖并通过检查；没有维护者私有路径、未说明的二进制或签名材料 |
| P1 | 更清晰的任务进度 | 下载量/总量/速度/剩余时间；解密独立阶段与进度；未知长度显示活动状态；取消后能解释保留了哪些文件 |
| P1 | 凭据“已验证匹配”的导航 | 以短指纹和来源区分，不只显示 Apple ID；展示验证过的 App 和时间，未知归属可保留，重复密钥合并但不丢失证据 |
| P1 | 网页共享生命周期 | 默认短时、显式开始/停止，地址含随机访问令牌，可见当前分享文件，结束后旧链接不可用；不常驻暴露整个下载目录 |
| P1 | Mac 更新/重复打开流程 | 明确运行副本位置，更新前退出后校验，激活已有实例；正式分发考虑签名和公证，覆盖 Finder 重复打开回归 |
| P1 | 导出脱敏诊断 | 一键复制阶段/状态码/版本/系统和操作标识，过滤账户、令牌、Cookie、密码及文件内容；不用反复手工截图 |
| P2 | 抽取双端共用核心 | 先提取纯模型、许可证解析、错误类型和任务状态；登录/文件选择/USB等平台差异保留适配层，避免认证一次性大重构 |
| P2 | 平台体验 | Mac 支持多选、拖拽、快捷键与详情面板；iOS 后台/锁屏和低空间提示，文件选择失败时可切十六进制或分享导入 |
| P2 | 本地密码与备份保护 | 尊重可选文件保存策略，补单独删除、备份排除和清除范围说明；可评估可选加密，不能将文件权限称为加密 |

后台下载应先确认当前桥接下载路径如何迁移或适配系统能力，不能只增加 UI 开关就宣称应用退出后仍下载。Apple 的 [后台文件下载文档](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background) 可作为实现参考，完成后还需真机锁屏、系统终止和重连测试。

建议下一轮先做“账户状态与失败恢复”，再做进度/后台，最后抽共用模块。这样优先解决下载中断和无处处理失败的问题，同时降低破坏现有 TestFlight 登录的风险。
